How to write checks

Each check runs one query and compares the result with one or more expectations:

row_count: 0Exactly this many rows, or a range: row_count: {min: 1}. A query for the violations with row_count: 0 lists exactly the records to fix.
all_rows: fte > 0 and fte <= 1Every row meets a rule (columns, arithmetic, comparisons, and, or, not, in, abs, round).
regression: {keys: [contract_id]}Same result as the stored baseline. Capture a baseline first on a known-good state.
reconcile: {connection: sf, query: ..., keys: [userId]}Same result as a query on another connection, for example source against target.
equals: {rows: [...]}Exactly these rows.

On SAP Datasphere the query is SQL (SELECT only). On SAP SuccessFactors it is an OData path, for example EmpJob?$select=userId,startDate,costCenter&$filter=company eq 'ACME'.

Write the business requirement in plain words to Claude Code with the write-scenario skill to get the checks drafted from the real column names.
